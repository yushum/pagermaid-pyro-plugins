# linkcopy

将 Telegram 消息链接替换成原文或媒体。使用运行 PagerMaid 的账号读取来源，无需额外机器人、API 密钥或依赖。

## 使用

在想发送内容的聊天中输入：

```text
,linkcopy https://t.me/example/123
,linkcopy https://t.me/c/1234567890/123
```

也可以回复一条含链接的消息发送 `,linkcopy`，支持隐藏超链接；被回复消息必须恰好包含一个有效的消息链接。仅回复取链接时，该消息会保留，插件只替换或删除自己的命令消息。

- 文字：直接将命令消息编辑成原文，保留粗体、超链接、自定义表情等 Telegram 文本实体。
- 媒体：复制图片、视频、文件、音频、语音、动图、贴纸、视频圆消息；发送成功后删除命令消息。
- 相册：默认复制链接所在的整个相册，保持顺序和每项配文。添加 `--single` 或使用带 `?single` 的链接，只复制选中的一项。
- 位置：在当前聊天、当前话题发送；显式提供链接时，保留命令的回复关系。

```text
,linkcopy https://t.me/example/123 --single
```

支持公开链接、`t.me/c/...` 私有链接、含话题 ID 的链接、`t.me/s/...` 预览链接，以及 `tg://resolve?...&post=...`、`tg://privatepost?...&post=...`。`?comment=...` 会读取对应讨论组的评论。

## 批量搬运（链接区间）

在目标聊天发送起始链接和结束链接即可，**包含两端**，按消息 ID 从小到大扫描。例如：

```text
,linkcopy https://t.me/HGLW889/45916 https://t.me/HGLW889/45994
```

这会处理 `45916–45994` 共 **79 个消息 ID**，把其中可读取的文字、视频及其他支持的媒体发送到当前聊天；不限定为视频。也支持两个链接中间加 `到` 或 `-`：

```text
,linkcopy https://t.me/HGLW889/45916 到 https://t.me/HGLW889/45994
```

- 两个链接必须指向同一频道或群组，结束 ID 不小于起始 ID；每次最多 **1000 个消息 ID**。公开、私有、话题链接均可，评论链接暂不支持批量。区间按整个聊天的消息 ID 扫描，**不会按话题筛选**；不能混用用户名链接和 `t.me/c/...` 链接作为同一区间的两端。
- 已删除、缺失、服务消息及不支持的消息类型自动跳过，并计入统计。来源无权访问、相册不完整、读取或发送出错时中止，不会悄悄跳过这些错误。
- 默认保留相册及配文，同一个相册只发送一次；相册跨越区间边界时，**只发送区间内的成员**。添加 `--single`（或任一端链接带 `?single`）则把区间内每条媒体单独发送。
- 批量文字另发新消息，保留文本实体；媒体仍优先复用文件引用，被明确拒绝后才下载重传。保留目标话题和命令的回复关系。
- 每次成功发送一条消息或一个相册后至少间隔 1 秒，并处理短期限流；命令消息约每 10 秒更新进度，完成后保留统计。每个目标聊天同一时间只运行一个批量任务。
- 在同一目标聊天发送 `,linkcopy cancel` 可请求停止。**当前下载或发送会先完成**，之后停止，报告已发送数量和下一条未处理链接；用该链接与原结束链接可继续。
- 网络或发送错误会立即中止剩余任务，保留进度和出错位置。出错的消息或相册可能已经送达，**先检查目标聊天再选择续传起点，不要直接重跑整个区间**。任务进度只保存在内存中，插件重载或进程重启后不会自动恢复。

## 内容保护与失败处理

所有媒体（包括带内容保护标记的消息）均先尝试复用 Telegram 文件引用，成功时无需下载上传。只有收到明确的内容保护或文件引用错误，才下载到服务器临时目录后重新上传。相册也先尝试整组复用；需要重传时，先下载完所有项目，再整组发送。

下载和重传消耗服务器磁盘、流量和时间，大文件会较慢；成功、失败或任务取消后均清理临时目录。失败时保留命令并显示原因。网络超时不会自动重发，避免重复发送；请先检查目标聊天后再决定是否重试。

### 大文件下载加速

无需额外参数。对大小已知且 **≥16 MiB** 的媒体，支持的 Pyrogram 版本会自动使用 **4 路并行分块请求**，每块 1 MiB；按绝对偏移写入临时文件，而不是按网络返回顺序拼接。逐块检查长度，完成后再检查文件大小，避免乱序、截断或缺块的文件被上传。下载期间约每 3 秒显示百分比、已下载大小和平均速度，下载完成后切换为上传提示。

- 复用已有文件引用仍是第一选择，成功时完全不需要下载；加速只作用于确实需要下载重传的情况。
- 小文件、大小未知的媒体，以及缺少所需接口的旧版 Pyrogram，继续使用原生下载器。遇到 CDN 重定向时，先取消并等待所有分块任务结束、删除残片，再交给原生下载器完成 CDN 解密和哈希校验。
- 网络错误、长期限流、分块长度错误不会偷偷切换原生下载器重跑；任务停止并报告错误。短期限流仅重试被拒绝的分块。取消或失败时先停止并排空所有 worker，再清理文件。
- 插件内最多同时运行一个并行下载，每个文件最多 4 个在途分块请求；不并行搬运整批消息，不修改客户端的全局并发设置，也不额外创建或关闭共享连接。相册仍在全部下载成功后才整体上传。
- 此优化是已有媒体连接上的并发请求，不是 4 条独立 TCP 连接。实际提速取决于 Telegram/DC 限速、往返延迟、服务器带宽、磁盘和加密性能，**不能保证固定倍速**。本次验证环境的 Pyrogram 已对大文件上传使用 4 个 worker，因此保留其原生上传实现，不另行替换。

思路参考 [FastTelethon 并行传输 gist](https://gist.github.com/painor/7e74de80ae0c819d3e9abcf9989a8dd6)，但该实现使用 Telethon，不能直接用于本插件；这里基于 Pyrogram 的文件 ID、媒体会话和原始 `upload.GetFile` 请求独立实现，不新增 Telethon 或其他依赖。

权限不足、网络超时或没有发送结果时，不会改用下载重传；重传再次被拒绝时也不会循环尝试。

需要当前账号能够读取来源；私有频道或群组通常需要先加入。插件不会自动加入聊天，也无法读取已删除、不可访问的消息。Telegram 服务端限制仍可能导致下载或重传失败，不能保证所有受保护内容都成功。

服务消息、投票、位置、联系人、付费媒体等暂不支持；不复制消息按钮、转发来源、原消息的浏览量或互动数据。普通粘贴链接不会触发，需使用 `,linkcopy`。只接受当前账号自己的命令，不开放给 sudo 用户。

已在 PagerMaid-Pyro 1.5.13 与其配套的 TeamPGM Pyrogram 上完成离线验证；Telegram 账号在线发送仍需实际验证。
